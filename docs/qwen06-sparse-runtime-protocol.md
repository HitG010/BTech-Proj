# Qwen3-0.6B fresh sparse guard runtime

This is a separate, local diagnostic runtime for the already prepared `qwen06-guard-fresh228-v1` question-only child. It does not amend the completed 64-question study, the cached pilot, their scores, or the prepared policy/protocol. It tests the frozen **plain confidence OR gold-free v7 parser rejection** guard against the same-threshold plain-confidence policy. A positive result is a further-study screen, not superiority confirmation. Docker remains running; no API/cloud or Kaggle task is part of this runtime.

Freeze this script, its tests, and this document before `prepare`. The one-time `prepare` command writes only `qwen06-sparse-validation-v1/runtime-v1/`. It verifies the prepared policy/review/question protocol/child dataset, all 2,652 closed-study inventory pins through the frozen pilot checker, frozen Qwen3-0.6B local assets, all 456 precompiled job IDs/seeds, numeric-v7 and generation implementations, source/test/doc hashes, and environment. The runtime plan pins the source artifacts. It constructs no model and reads no reference. An independent prelaunch audit must create a checksummed `prelaunch-review.json` in `runtime-v1` whose payload is `{"plan_sha256":"<digest of runtime plan>","prepared_file_sha256":"<digest of plan.prepared_file_sha256>","decision":"independently_audited_allow_launch"}`. `launch` refuses without that exact marker. The audit must inspect actual prepared inputs, resource arithmetic, source pins, and collection endpoint before any model operation.

The collector runs the 228 frozen direct jobs first, each once per invocation in frozen order. It reuses the prepared Qwen3-0.6B model revision, tokenizer, prompt, decoder, backend metadata, job seeds, and caps. It validates each result against the frozen job. Only after **all 228 direct results are complete and accounted** does it write the immutable eligibility mask, derived solely from direct postwarper confidence and gold-free v7 extraction using the previously fitted threshold. Eligibility is `parser rejection AND plain-confidence accept`. More than 32 eligible questions stops as a resource failure: there is no subsampling, thinking run, scoring, or reference access. For at most 32, only their precompiled thinking jobs run; all others remain potential jobs only. A failed/unknown attempt retains its full reserved token/second charge until a valid settlement; settled valid failed output charges its actual tokens. No quality retry or automatic resume occurs.

The cumulative runtime ceiling is 250,000 tokens and six hours, with the wall origin written at the first launch reservation and admission based on the larger of wall age (including sleep and gaps, even if the first supervisor fails before a worker starts) and charged setup/job seconds. Setup is at most 900 monotonic seconds per invocation; each job is at most 600 monotonic seconds, clipped to remaining global time. At most two setup sessions, collector invocations, and detached supervisor launches exist: one initial launch and at most one **explicit** resume after a runtime failure. Integrity, resource, or budget stops are not resumable. On resume, an unresolved operation from a previously observed nonzero collector exit remains charged at its full reservation; the final endpoint permits it only with the prior failed supervisor and process evidence, while every current operation must settle. One worker runs at a time. The detached `/usr/bin/caffeinate -s -i` process requires AC, full-wake and stable no-model clock preflight; the user must keep the lid open. The native collector also uses the existing process-scoped macOS user-activity guard. Two-second polling watches monotonic operation anchors and a 9 GiB sampled RSS ceiling. This does not guarantee prevention of user sleep, thermal interruption, or actual total unified-memory usage.

The finalizer is a distinct child process. It requires an exited successful collector, immutable full direct mask, all selected thinking results, fully accounted ledger, live wall/token budget, source/parent and protected-original preservation. Current operations must settle. A valid result published before its receipt may count only after the prior failed collector is observed exited and its supervisor is terminal; that operation retains the full reservation charge. The eligibility timestamp follows that exit evidence. It opens the upstream Arrow `answer` column **only for the M eligible selected training indices**, after a one-time score-start marker. M=0 opens no reference and has no score-start marker. Numeric-v7 scores only eligible thinking outputs; a validated existing sidecar is reused without reopening references, and a marker without a valid cache prevents a second fetch. The fixed-action analysis assigns zero increment to every unchanged question and `Ythinking − 0.05 × thinking_tokens/1000` to each eligible question, because v7 rejected its direct output. It reports the 228-question mean, 95% whole-question bootstrap interval (2,000 draws, seed 20261018), incremental accuracy/cost, event rate, conditional thinking accuracy, and the predeclared +.01/lower-bound-positive further-study screen. It must not report absolute full-policy accuracy/utility or an always-thinking counterfactual. Parent preservation is checked before and after references. A one-time report and terminal supervisor finish record close the runtime.

After freeze and the independent prelaunch audit, the operator commands are:

```sh
.venv/bin/python -m scripts.qwen06_sparse_collect prepare
.venv/bin/python -m scripts.qwen06_sparse_collect status
.venv/bin/python -m scripts.qwen06_sparse_collect launch
.venv/bin/python -m scripts.qwen06_sparse_collect status
```

`resume` is a separate manual command permitted only once after an eligible runtime failure. Never call private `collector`, `supervisor`, or `finalize` directly. Status is read-only. Do not reset journals, prepare again, rerun a completed endpoint, alter prepared assets, access official-test labels, or expand the 228-question role under this protocol.
